One loss to report: FAISS's float HNSW beats Strata's float path at high recall on this dataset. The quantized path is where Strata wins. Repeat runs vary about ±15% on this VM, so compare rows within a table.

What changed in the code

  • SQ8 quantization: one byte per dimension, with AVX2, NEON and scalar kernels that agree to 1e-6. The graph is built at full precision and the top candidates are re-ranked exactly. Index.load(path, mmap_vectors=True) keeps the float vectors on disk.
  • Inserts no longer block reads: a two-phase insert. Queries copy neighbour lists under 1-byte spinlocks only while a batch is linking, and keep the lock-free path otherwise. Verified with ThreadSanitizer.
  • Filtered search: brute force when |allowed| ≤ √(M·ef·n), instead of a fixed 2,048-label cutoff. The label map is now a prefetching open-addressing table (~14 ns vs ~170 ns per lookup).
  • A rare reachability bug, present in the original code: about 1 in 1,500 small parallel builds could miss a node. It is fixed with an exact scan whenever ef ≥ index size.
  • Tried and rejected: ACORN-style two-hop filtered traversal. It was slower and less accurate here, and the reasons are written up in DESIGN.md.

Open problems: Google DeepMind's AlphaEvolve repository

This repository holds 67 open problems from Georgiev, Gómez-Serrano, Tao and Wagner (2025). It accepts improvements through GitHub issues and credits outside contributors by name. I attacked two of the problems.

Problem 61, ring loading (open since 1998): an exact certificate for C ≥ 47/42

AlphaEvolve published its bound as a float, 1.11904756847…. Linear-programming polish shows the true vertex is exactly 47/42. I found a rational instance with α = 47/42, verified in exact fraction arithmetic over all 215 sign choices. This makes their bound rigorous; it matches their value and does not beat it. A ready-to-post GitHub issue in your name is attached. Larger instances (m = 17, 19) found nothing above 47/42 in about 2 CPU-hours.

Problem 59, largest isosceles-free subsets of the n×n grid

The records are 164 points at n=100 and 112 at n=64 (AlphaEvolve), and 58 at n=32 (posted 4 Oct 2026). I built a C++ toolkit: tabu search with exact incremental conflict tables, symmetric iterated local search, an exhaustive (k, k+1)-swap certifier, SAT encoding, and large-neighbourhood search with exact SAT repair. The records survived:

  • n=100: the set is exactly 4-fold symmetric, and no swap of up to 3 orbits for 4 improves it (10,660 triples checked).
  • n=64: no 2-for-3 point swap improves it (6,216 pairs).
  • n=32 (58 points): no 4-for-5 swap (424,270 subsets) and no 6-for-7 mirror-orbit swap (475,020).
  • LNS + SAT: 47,818 windows at n=100 and 8,984 at n=64 proved unrepairable.

I also built explicit, verified sets for sizes with no published value: n=48 → 80, n=80 → 120, n=128 → 176. They are probably far from optimal, so I would not post them as records.

In plain terms, these records are very deep local optima. A real improvement probably needs days of compute; the plan and code for that are in math/MATH_RECORDS.md.
