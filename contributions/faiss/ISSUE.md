IndexHNSWFlat: a group of identical vectors larger than 2M becomes partly unreachable and traps searches

---

When a group of identical vectors is larger than a level-0 neighbour list (2M), `IndexHNSWFlat` cannot find part of the group. A search that reaches the group can also return fewer than `k` results, even with `efSearch` far above `k`.

```python
import numpy as np, faiss
rs = np.random.RandomState(0)
base = rs.randn(16).astype("float32")
xb = np.vstack([np.tile(base, (200, 1)), rs.randn(800, 16).astype("float32")])  # 200 copies + 800 others
index = faiss.IndexHNSWFlat(16, 32); index.hnsw.efConstruction = 100; index.add(xb)
params = faiss.SearchParametersHNSW(efSearch=1000)
_, I = index.search(base[None], 200, params=params)
print(len(set(I[0].tolist()) & set(range(200))))  # 135: only 135 of the 200 copies are found
_, I = index.search(base[None], 300, params=params)
print((I[0] >= 0).sum())                          # 135 results for k=300, from an index of 1,000 vectors
```

- **M=16:** the same script finds 166 of the 200 copies and returns all 300 results.
- **hnswlib:** with the same M, `ef_construction=100` and `ef=1000`, it finds all 200 copies at both M values.
- **Sink repair:** `add_level_0_links_from_sample()`, run with the 1,000 vectors plus 1,000 perturbed copies as the sample, finds no sinks and changes nothing.

Measured on `main` at c11a75c.

### Cause

Copies tie in their distance to a point being added, so they never prune one another in `shrink_neighbor_list` (`Comp::cmp(dist_v1_q, dist_v1_v2)` is strict). At level 0, `compute_forward_links_impl` and `add_links_starting_from_impl` keep `nb_neighbors(0)` = 2M targets. Algorithm 1 of the HNSW paper keeps M and leaves the rest of the list to reverse links.

Once the group is larger than 2M, each new copy's list therefore contains only copies. Reverse links from later points lose to the tied copies in `merge_reverse_links_impl`. So few or no edges leave the group, and copies whose reverse links all lose have no edges in. Level-0 lists for the script above:

| | copies with in-degree 0 | edges from a copy to a non-copy |
|---|---|---|
| M=16 | 28 of 200 | 3 |
| M=32 | 2 of 200 | 0 |

### Real data

I split 13 Python/C++ repositories (including FAISS, scikit-learn, pandas, sktime and mteb) at blank lines, as paragraph-aware RAG chunkers do. This gave 423,137 chunks. I embedded them with TF-IDF and a 64-dimension SVD; any deterministic embedder gives identical texts identical vectors. The index was `IndexHNSWFlat(64, 32, METRIC_INNER_PRODUCT)`.

- 17.6% of the vectors are exact duplicates, and 37 groups have more than 64 members. The largest group is FAISS's own license header, with 759 copies.
- A search for its own vector misses 1,045 duplicate chunks, even with `k=759` and `efSearch=512`.
- 645 searches for a duplicate chunk return fewer than 100 results for `k=100`.

I have a fix that keeps duplicate-free graphs byte-identical, and will open a PR referencing this issue.
